# 主动还是被动：谁拿走了流动性？（v4）

v2 沿用 v1 的口播（`script.json` / `口播文案.md` 原文未改，配音照旧读这一稿），重做的是画面信息层：固定安全区、实时数据标注、结论区和自动避让检查。

v3：画面跟紧配音——动作、标注、结论都落在关键词**开始**的那一帧（不再等词说完）；换场镜头在上一句说完就起飞、0.8 秒到位（原来约 1.3 秒，新一句开口后约 1 秒才到）；标注从 41 个加到 53 个，每个讲解节拍都有 1–2 个实时数据标注。

v4：标注直接贴在解释对象旁边——先在 150 px 内找空位（订单簿按每块挂单、每层层板、脉冲分别避让，标注可以落在层板之间），放不下再试 240 px，再换短标签（短标签也带数字）；同屏两个标注不排在同一行。`npm run ap:layout --leaders` 列出每个标注的引线长度（当前中位数约 54 px）。开头几根 K 线逐根长出来，再出大阳线。

竖屏 1440×2560、30 fps 的金融科普短片。Remotion + Three.js（@remotion/three），K 线、订单簿、主动单、Delta 全部由代码生成，没有视频素材和 AI 图片；中文用 Noto Sans SC / Noto Serif SC 原生渲染。行情是固定的示意数据，右上角始终标注「教学示意，不构成投资建议」。

口播文案见 [`口播文案.md`](./口播文案.md)（与 `script.json` 一致）。

## 画面

一整个 3D 交易舞台：深黑蓝底、反射地面、体积光、雾和景深。场景是沿 x 轴排开的几组"布景"，换场时镜头飞到下一组，镜头横移把上一组带出画面、下一组带进画面，上一组同时在换场后第 8–18 帧完全淡出，新场景的标注在换场 6 帧后才出现；没有黑场，也不会留下上一幕的残影。

- **K 线**：圆角倒角的立体方块，清漆高光、真实光照和投影；红涨绿跌。
- **订单簿**：一层层玻璃价位层板；**被动挂单**是透明玻璃板（上方 = 被动卖单，下方 = 被动买单）。
- **主动单**：一束脉冲（红 = 主动买，向上；绿 = 主动卖，向下），跨过价差，打到哪层，哪层玻璃板就被吃掉，旁边那根 K 线同步长出来——这就是"价格响应"。
- **成交量 / Delta**：地面上的玻璃柱是成交量，柱子里的实心芯是 Delta（红正绿负），和 K 线同时出现。
- **配色**只有五种：深黑蓝、暖白、金（关键价位、成交价）、红（主动买 / 上涨）、绿（主动卖 / 下跌）。

| line | 章节 | 画面（镜头） |
|---|---|---|
| L01 | 开场 | 第 0 帧结论区就是「一买就追高？」；一段横盘后长出一根大阳线（轻推近），标注 +2.2% 和「你的买点 102.70 · 接近最高」；「不是手慢」时结论换成「是没分清主动和被动」 |
| L02–L04 | 01 主动买 vs 被动买 | 订单簿 A：红色脉冲在「吃掉」之后跨过价差吃掉卖一，「推涨」时再吃卖二，K 线跟着长（推近看成交）→ 横移到订单簿 B：你的限价买单挂在下方，价格被别人推走，没成交 → 拉远并排对比 |
| L05–L06 | 02 主动卖 vs 被动卖 | 订单簿 C：绿色脉冲砸穿买一、买二 → 横移到 D：限价卖单挂在上方，主动买上来才成交 → 拉远：两边的主动单轨迹亮起，"有没有主动跨价 / 有没有推动价格" |

## 时间轴：全部由 line ID 驱动

- `script.json`：19 句口播原文（字幕基准）和估算参数。
- `timeline.json`：每句、每个字的起止帧，字幕分条，**总帧数也在这里**。代码里不写死任何帧号或时长。
- `events.json`：画面动作的命名时间点，写法是「哪一句 + 哪个词」，例如 `aEat = L02 的「吃掉」说完`。v3 起所有动作都从关键词开口那一帧开始（`at: "end"` 仍支持，但不再使用）。
- 仓库里提交的是**按字数估算的占位 timeline**（约 101 秒）。换成真实配音后跑一次 `npm run ap:sync`，字幕、动画、镜头、总时长自动跟着新时间走，不用改代码。

## 文件

- `Film.tsx`：成片 `ActivePassive`、封面 `ActivePassiveCover`。音频优先读 `public/activepassive/mix.wav`，没有就读 `public/voiceover/vo.wav`，都没有就静音。
- `world.tsx`：3D 舞台（K 线、订单簿、脉冲、量柱、区间、灯光、地面）。
- `acts.ts`：每个布景在某一帧的状态（挂单剩多少、价格到哪、脉冲在哪）。
- `director.ts`：镜头关键位和各布景的出入场。
- `layout.ts`：统一的 `LAYOUT` 常量（见下方「安全区」）和尺寸估算。
- `scene.ts`：每一帧 HUD 要画什么——结论、数据标注（文字、实时数字、位置）、状态栏，以及每个 3D 数据物体在屏幕上的矩形。纯函数，`hud.tsx` 照它画，检查脚本照它查。
- `hud.tsx`：按 `scene.ts` 画状态栏、数据标注（细引线 + 锚点）、结论区、字幕。
- `layoutcheck.ts` + `../../scripts/activepassive-layout.mjs`：不渲染、逐帧检查版面（`npm run ap:layout`）。
- `data.ts`：示意行情和舞台布局。
- `text.ts` / `fonts.ts`：画面文字；字体按这些字从 Google Fonts 取子集（渲染时需要联网）。
- `../../scripts/activepassive-sync.py`：估算 / 对齐 timeline、生成 SRT、混音、打印事件时间。
- `../../scripts/activepassive-stills.mjs`：按事件名抽帧检查，例如 `node scripts/activepassive-stills.mjs out/ap 0.5 aEat+20 cBig+10 cover`。

## 安全区（`layout.ts` 的 `LAYOUT`）

| 区域 | y 范围 | 放什么 |
|---|---|---|
| 顶部状态区 | 0–260 | 系列名、主题《主动还是被动：谁拿走了流动性？》、章节、步骤点、进度条、风险提示「教学示意，不构成投资建议」 |
| 主数据区 | 300–1760 | K 线、成交量、Delta、盘口，以及指向它们的数据标注 |
| 结论标注区 | 1780–1950 | 当前一句主结论 |
| 字幕区 | 1980–2320 | 只放字幕（最多两行） |
| 左右边距 | ≥ 64 px | 所有文字、卡片和数据 |

- 3D 镜头的主点上移 250 px（`viewShift`），舞台中心落在数据区中心，而不是画面中心。
- 同一时间最多：1 条主结论、2 个数据标注、1 条字幕。新元素在它的关键词开口时开始淡入（6 帧）；旧元素在下一个关键词之前用 5 帧淡完，不叠化。
- 数据标注只标当前口播讲的对象，带实时数字（挂单被吃掉的手数、成交价、Delta、距结构的距离等，均为示意数据）。位置不手写：`scene.ts` 在数据区里由近到远搜索锚点旁的空位，要求在它显示的整段时间里都不压任何 K 线、量柱、Delta、盘口和另一个标注，引线也不穿过另一个标注；放不下就换短标签，再放不下就不显示（检查脚本会报出来）。
- `npm run ap:layout` 逐帧检查：标注数量、标注出区 / 压数据 / 互相重叠、镜头静止时数据物体出区、结论和字幕是否装得下各自的区域；并按事件列出每个关键帧上显示的标注和结论。有问题时退出码为 1，`ap:make` 会在渲染前停下。换了真实配音、跑过 `ap:sync` 之后会自动按新时间重查。
- 这项检查用的是估算的文字宽度和 3D 包围盒，不能代替看画面：渲染前请用 `npm run ap:stills` 抽几帧看一眼。

## 本地使用（都在 `studio/` 下）

1. 放配音：`studio/public/voiceover/vo.wav`（wav，任意采样率，单声道或立体声）。这个目录已被 git 忽略，不会上传。
2. 安装：

```bash
npm install
pip install numpy scipy faster-whisper pypinyin
```

（`faster-whisper` / `pypinyin` 用于逐字对齐，第一次会下载模型；不装也能跑，会自动退回按停顿对齐。）

3. 对齐 + 字幕 + 混音（换音频后只需重跑这一步）：

```bash
npm run ap:sync
```

它会改写 `src/activepassive/timeline.json`，生成 `../outputs-activepassive-v4/active-passive-v4.srt` 和 `public/activepassive/mix.wav`（−14 LUFS，峰值 ≤ −1.5 dBFS），并打印每句的起止时间。`npm run ap:check` 会按时间顺序列出每个画面事件落在哪个词上，方便核对。

4. 渲染：

```bash
npm run ap:make
```

依次执行：类型检查 → 对齐/字幕/混音 → 版面检查 → 复制字幕 → 渲染 MP4 → 生成封面。没有独显时用 `npm run ap:make:cpu`。

输出：

- `D:/责苏/codex保存/active-passive-v4.mp4`
- `D:/责苏/codex保存/active-passive-v4-cover.png`
- `D:/责苏/codex保存/active-passive-v4.srt`

## 对齐说明

- **逐字（默认）**：faster-whisper 识别 vo.wav 的词级时间，再用动态规划把识别出的字逐个对到文稿的字上（同字或同拼音都算对上），没对上的字在相邻字之间插值。识别率低于 70% 会打印警告。也可以 `python scripts/activepassive-sync.py align --words my-words.json` 传入任意词级时间戳。
- **按停顿（备用）**：`--pauses`，或者没装 faster-whisper 时自动使用。按能量找停顿，用动态规划把停顿和文稿标点一一对应；短语内按字平均分配。
- 用合成测试信号验证过：按停顿对齐的句首误差 ≤ 0.04 秒；逐字对齐（8% 漏字、5% 错字）平均误差约 0.05 秒。

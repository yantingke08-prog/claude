# 同一根大阳线，为什么结局完全不同？（v3）

v3 放弃了 v2 的图表底层，直接基于 v1 的文案、配音和时间轴重做。配音与 v1 完全相同，片长 86.23 秒（2587 帧，30 fps）。红涨绿跌，1080×1920，另有原生 2K（1440×2560）。

## 架构变化

| | v2 | v3 |
|---|---|---|
| K 线与面板 | 3 个 3D LaneMesh 从第 1 帧渲染到最后一帧 | 固定的 SVG/DOM 二维层，每个场景一层 |
| 背景网格 | 3D shader 平面 | 屏幕空间静止的 SVG 网格 |
| 3D | 全片 | 只用于开场微距和一次拉远（帧 0–39），之后画布卸载 |
| 镜头 | 开场后锁定，但还有 shake 字段 | 帧 40 起没有相机；`shake` 字段和震动代码已彻底删除 |
| 换章节 | 面板在两套版式之间插值滑动 | 整个图表层硬切替换；唯一的 4 帧溶解是 3D → 2D 交接 |
| 中间章节 | 主图 + 另外两条缩略图 | 每章一张完全不同的图，不带缩略图 |

## 规则检查（由脚本完成）

- `timing-report.md`（`npm run sc3:timing`）检查以下规则：
  - 换章前，上一句旁白结束已满 18 帧；
  - 标注在关键词出现时，或提前 4–8 帧出现；
  - 普通标注停留 ≥ 24 帧，卡片停留 ≥ 36 帧；
  - 标注只出现在当前可见的图上，且图表落位之后才出现；标注指向的 K 线已经画出；
  - 同时最多 1 张主说明卡；
  - 每行不超过 12 个汉字；
  - 旁白进行中，每 ≤ 2.5 秒有新信息。
- `motion-report.md`（`npm run sc3:seq` 后运行 `npm run sc3:motion`）检查帧间位移：
  - 把全片按 1/4 尺寸逐帧渲染成 PNG，相邻两帧逐像素比较；
  - 没有安排变化的帧，必须与上一帧完全相同（位移为 0）；
  - 每一处变化，都必须对应已安排的标注、K 线生长、字幕或切换。

## 本地渲染（Windows，需要 Node 18+ 和网络）

```bash
git clone -b same-candle-v3 https://github.com/yantingke08-prog/claude.git
```

```bash
cd claude/studio
```

```bash
npm ci
```

2K（1440 × 2560）：

```bash
npm run sc3:make:2k
```

1080 × 1920：

```bash
npm run sc3:make
```

两条命令都会依次完成：

1. 复制 SRT；
2. 渲染成片；
3. 生成封面；
4. 校验：时长 60–90 秒、分辨率、H.264 yuv420p、30 fps、AAC 立体声、完整解码、封面尺寸。

最后一行输出 `All checks passed.` 即为通过。没有 GPU 时用 `npm run sc3:make:cpu`。成片用单标签页渲染（`--concurrency=1`），保证静止帧逐像素不变。

v3 中只有开头 40 帧是 3D，其余都是二维层，所以渲染比 v2 快得多。

## 报告

| 文件 | 内容 |
|---|---|
| `timing-report.md` | 换镜等待帧数、每条标注的关键词提前量、停留帧数、所在图表、锚点、汉字字数、信息节奏 |
| `motion-report.md` | 全片逐帧位移检查：相邻两帧无变化的有 1771 对，有变化的 815 帧都能对应到已安排的标注、K 线生长、字幕或切换，无法解释的变化为 0 |

位移检查在制作中发现并修正了三类问题：
- 渐变、模糊和阴影在不同渲染标签页之间有 1–5 级的光栅差异；现在全部改为纯色。
- 嵌套的组透明度在部分帧上合成结果不一致；现在透明度直接写在每个图形上。
- 多个渲染进程并行、机器负载高时，偶尔会在 Chrome 画完之前截下这一帧。

因此，成片渲染命令统一使用单标签页（`--concurrency=1`）。复查方法：先运行 `npm run sc3:seq`（约 1 小时，CPU），再运行 `npm run sc3:motion`。

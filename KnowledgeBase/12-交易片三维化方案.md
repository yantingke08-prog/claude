# 12 《交易正期望》三维化方案

## 问题诊断

成片像 PPT，根因在实现方式：

- 讲解主体（资金曲线、面积图、扇形图、直方图、公式）全部是 HTML / SVG / Canvas 2D，被固定在屏幕平面里
- Three.js 只负责全片共用的背景粒子云 `Ambient`，背景在动，主体不动，所以没有空间感
- 第二关的"从 10 笔缩放到 1000 笔"只是 2D 横轴的重新标定，不是镜头运动
- 动态基本只有元素的进场和退场，数据本身没有在空间中移动

## 原则

1. **讲解对象本身进入三维空间**，不加装饰性的粒子、光效或边框来"假装"三维
2. **空间坐标必须有含义，并且整段固定不变**：例如 x = 第几笔，y = 累计盈亏，z = 第几个人。镜头可以移动，坐标比例不能偷偷改
3. **粒子 = 数据个体**：一个光点就是一个人、一笔交易或一次结果，粒子的聚散对应统计过程
4. **最后落在可读的视角上**：每段结尾用长焦、正对数据的近正交视角给出结论，刻度和关键数字用 HTML 投影标注，保证清晰
5. **屏幕固定的读数只留关键数字**（笔数、亏钱比例），公式和结论的大字仍用 2D，但要贴在空间位置上，或在三维场景之后出现

## 样片：第二关 大数法则（已实现）

- 代码：`src/expectancy/three/LlnSpace.tsx`（空间、镜头、几何），`src/expectancy/scenes/LargeNumbers3D.tsx`（编排与标注）
- 合成：`Exp-lln-3d-sample`（带字幕和配乐，26 秒），`Exp-lln-3d-clean`（隐藏字幕、章节卡和装饰背景，用于验收主体画面）

| 段 | 画面 | 空间 / 粒子的含义 |
|---|---|---|
| 一个人 | 微距跟拍"其中一个人"的资金线，每笔跳出 +2.5 / −1 | 一笔一笔的累积 |
| 一千人 | 镜头后拉绕到侧面，999 条轨迹按 z 从前往后依次亮起 | z = 不同的人；每个光点 = 一个人当前的盈亏 |
| 10 → 100 → 1000 笔 | 数据持续生长，镜头随之真实地拉远、升高 | 缩放靠镜头，不靠改坐标 |
| 期望值 | 斜面 y = 0.4·x 穿过所有人的轨道；1000 人的平均线贴着斜面走 | 收敛到期望 |
| 分布 | 镜头飞到终点线外回望，1000 个光点离开轨道，按最终盈亏落进直方图 | 分布由一个个人堆出来 |
| 读数 | 长焦正对，出现刻度和"第 1000 笔"终点门 | 结论清晰可读 |

技术要点：

- 1000 条 × 280 个顶点的轨迹做成**一个静态几何体**，揭示进度、人群点亮和水下变红都在着色器里完成，每帧只更新几个 uniform
- 前 100 笔逐笔保留顶点（微距镜头需要细节），之后每 5 笔取一个点
- 盈亏 = 0 的地面只铺到当前数据的范围，避免微距画面被大平面占满
- 镜头 `camAt(frame)` 是关键帧插值的纯函数，WebGL 场景和 HTML 标注共用它，标注能精确贴住三维位置

## 风格原则（2026-11-01 与用户确认）

- **风格不限，平面和三维结合**。核心要求：现代审美、审美要高，**绝不能像 PPT 那样平**
- 统计过程（成千上万人、上万次结果）放进**真实三维空间**，用镜头的推拉摇移来叙事
- 公式、结论、读数用**空间玻璃卡片**（`GlassCard`：背景模糊透出后面运动的画面、顶边高光、随角度滑动的反光、真实的透视倾斜）加上灵动的 MG 动效
- 倾斜卡片、底纸都可以用，但要通透、有景深，不能是贴在屏幕上的平面

## 全片现状（已实现）

| 章节 | 文件 | 画面 |
|---|---|---|
| 开场 | `scenes/Hook3D.tsx` | A、B 两条资金线在玻璃"爆仓地面"上方赛跑；每笔交易喷出绿/红粒子；A 砸穿地面，400 颗粒子碎散，地面泛起冲击环，镜头震动；最后镜头升起给出标题。玻璃名牌跟随线头 |
| 第一关 期望为正 | `scenes/Expectancy3D.tsx` + `three/Trays.tsx` | 10×10 玻璃托盘：每格一笔交易，赢的长出绿柱、亏的沉下红井；排序后镜头转到侧面，**侧视图就是面积图**（宽 = 概率，高 = 盈亏，标注尺寸线）；公式在玻璃卡片上 |
| 第二关 次数足够 | `scenes/LargeNumbers3D.tsx` + `three/LlnSpace.tsx` | 透视玻璃板上的抽签小球（带投影弹跳）→ 1000 条空间轨迹 → 1000 格连亏条躺在玻璃平面上，镜头推近连亏处 |
| 第三关 仓位能活 | `scenes/Sizing3D.tsx` + `three/SizingSpace.tsx` | 两组人在平行跑道上（对数高度），红色"亏掉九成"玻璃地面，下面是深渊；40% 组成片坠落。抛硬币：一万颗粒子 = 一万个玩家，每把左右跳动重新堆叠成分布，平均值与中位数是两道光柱，越分越远 |
| 第四关 执行纪律 | `scenes/Discipline3D.tsx` | B 的托盘重现：绿柱被削矮（赚一点就跑），镜头钻到玻璃下仰视红井被挖深（亏了死扛），期望实时翻负；加倍下注是 5 口逐级加深的红井，镜头俯冲下去；最后四张玻璃卡片翻入 |
| 结语 | `scenes/Outro3D.tsx` | 第二关的 1000 人空间在后方缓慢环绕，金句逐字浮现，风险提示放在玻璃卡片上 |

共用工具在 `three/common.tsx`：`makeCamera`（关键帧镜头）、`withShake`、`projector`（三维坐标到屏幕的精确投影）、`Label`、`GlassCard`、`StudioLights`。

### 防误导的镜头规则（踩过的坑）

- **不要从数据背后拍时间轴**：从背面看，x 轴左右翻转，下跌会被看成上涨。第三关 40% 组的特写最初就犯了这个错，后来改成从正面、地面以下仰拍
- 刻度会裁剪的地方要明说：第三关跑道的高度被限制在 1/10⁶ 到 ×1000 之间，超出的极端值贴在边界上

## 渲染交给云端 GPU 电脑

本机没有显卡，只负责写代码和抽查关键帧；完整渲染在云端 Windows（有 GPU）上做：

```bash
git pull
```

```bash
cd studio && npm ci
```

```bash
npm run exp:sample:gpu
```

输出 `studio/out/samples/lln-3d-sample.mp4`（26 秒，带字幕和配乐）。验收主体画面时，用 `npm run exp:sample:clean:gpu` 渲染不带字幕、章节卡和背景的版本。

`*:gpu` 脚本会传入 `--gl=angle --concurrency=50%`。命令行参数优先于 `remotion.config.ts` 里的 `swangle`，所以不用改配置文件。如果画面出现黑屏或 WebGL 报错，先去掉 `--gl=angle` 回退到软件渲染，排除是显卡驱动的问题。

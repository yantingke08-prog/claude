# 战前觉醒 · 第 1 期（v6）：本地渲染说明

这是 1080×1920 竖屏（交付用原生 2K 1440×2560）、172.4 秒（2 分 52 秒）的中文知识科普短片。主题是市场拍卖、参与者角色、三种订单（被动 / 主动 / 止损），以及从“看 K 线结果”到“看订单原因”的转变。

- 技术方案：Remotion 4 + React Three Fiber（WebGL 实时 3D）+ 后期（泛光、景深、颗粒、暗角）。每一帧都是帧号的纯函数，所以每次渲染结果完全一致。
- 代码：`studio/src/zhanqian/`
- Remotion 合成：`Zhanqian`（成片），封面是 `ZhanqianCover`
- 本目录文件：
  - `script.md`：逐字稿，带时间码；
  - `storyboard.md`：基础分镜和本期取舍；
  - `audio.md`：字幕、配音、音乐、音效的配置方案；
  - `subtitles.srt`：外挂字幕；
  - `cover.png`：竖屏封面；
  - `keyframes/`：关键帧预览图（`contact-*.jpg` 是拼图），以及 `keyframes/README.md` 的逐张说明；
  - `timing-report.md`：每个标注的停留帧数和每个切点的余量（`npm run zq:layout` 自动生成）。
- 仓库里**不包含**成片 MP4。

## v6 改了什么（事实和旁白字词不变，不加硬切，2K 和手机安全区不变）

- **每句话一个视觉重点**：同一时刻最多 1 个主标注（说明卡、结论大字或结果胶囊）+ 1 层辅助数据。v5 常驻的成交带 / 价格阶梯 / 差值 / 最新价 / 价差条不再同时出现，每个镜头只留一种数据层；标注按句交接，不叠加。
- **分类讲解的顺序**：三种订单、四类参与者都先给总览（只有编号和图形，元素很少），再在顶栏点亮当前类别，然后用镜头推近或原画面框选给出证据，最后在说明卡最后一行落结论。
- **时机**：
  - 标注在旁白念到关键词前 0–8 帧开始出现（实际是前 6 帧）。关键词时间改用配音的逐词时间戳，不再按字数估算。
  - 普通标注完全展开后至少停留 24 帧，说明卡至少 36 帧，不会刚出现就切走。
  - 每个切点都落在句子结束后 18 帧（p6 处 24 帧）。原来切在句子中间的 4 处，在原句里插入 1.0–1.4 秒停顿，字词不变。
  - 时间不够的地方都是延长镜头：句间停顿加长，回顾三行结论前留 4.6 秒。全片因此从 144.3 秒变为 172.4 秒。
- **一个镜头一个动作**：镜头运动约 18 帧内停稳（开场升镜和结尾推镜除外），之后才出标注。
- **订单墙构图**：12 个订单墙镜头分别用 9 种构图，相邻两个从不重复。
  - 正面全景、低机位侧面、俯拍买墙、分屏版式（盘口在上半屏、价格路径在下半屏）、背面反打、近景特写、拉远全景、左侧远景文字版式、仰拍拍卖锤。
  - 每个构图的数据层也不同：价格阶梯、成交带、价格路径、幽灵订单、计数器。
- **音效**：whoosh / thud 只在 7 个章节起点和两个大转折（穿入 K 线、止损连环引爆）。数据标注出现时只有一声轻 tick；普通切点、说明卡和每位参与者出场都不再配响声。
- **保留**：v5 的水平 OHLC 和不交叉连线、手机字号、安全区和防遮挡。
- **自动检查**：`npm run zq:layout` 新增以下检查。逐帧检查 5,173 帧、102 个标注、30 个切点，0 个问题；最短停留 24 帧，切点距句末最短 18 帧。
  - 同屏主标注 / 数据层的数量；
  - 每个标注相对关键词的出现时间；
  - 是否在镜头稳定后才出现；
  - 停留帧数；
  - 切点和句子结束之间的帧数；
  - 订单墙构图是否连续重复。

  每个标注从“完全可见”到“离开或切镜”的停留帧数写在 `timing-report.md`。

## v5 改了什么（32 个连续镜头不变，旁白和知识点不变）

- **镜头内节拍**：每个镜头先给主视觉，再加数据层，最后落结论；新标注出现、数字变化、框选移动、阶梯跳档、成交带新增、路径延伸、对比线、仪表更新，约每 1.5–2.5 秒一次。没有新增硬切，也没有缩放跳变。
  - 自动检查会逐镜头统计“节拍”。v5 结果：32 个镜头都不存在超过 2.5 秒的空档。
- **常驻数据层**（盘口类镜头）：左侧成交带和“主动买 − 主动卖”差值条，右侧价格阶梯和最新价 / 跳档数，顶部章节进度条。它们按“成交带 → 阶梯 → 差值 / 最新价”的顺序依次进入，不会一开场就堆满。
- **新增约 25 处标注**，按功能分成不同组件：
  - 数字卡（无边框、深色渐变底）；
  - 关系引线牌（左侧细色条）；
  - 结果胶囊（实色底、深色字）；
  - 风险徽章（琥珀描边 + 警示符号）；
  - 关键位虚线（左端标签）；
  - 对比条（左右两色）；
  - 路径 / 成交量缩略图。
- **OHLC（1:52 左右）**：右侧固定四行“开盘 / 最高 / 最低 / 收盘”；每个价格先水平接到一根垂直汇总轨，再水平进入对应行，四条线不交叉；旁白读到哪一项只亮哪一行，读完四项后恢复同等亮度。所有文字始终水平。
- **视觉系统**：深石墨背景、12 栏网格、半透明深色玻璃面板 + 细金属描边；统一 2px 线宽和圆角；去掉粗描边和霓虹外发光，3D 泛光降低约 30%；所有出现动画改成平滑缓入缓出，不再弹跳。
- **手机竖屏**（按 390×693 预览检查）：
  - 关键文字都在左右 60px、顶部 140px 以内，底部 580px（1340px 以下）不放关键数据；右侧 120px 平台按钮区不放文字。
  - 字幕 58px，位于 1374px 附近。
  - 最小字号 34px，标签 40–48px，数据 48–80px，结论 90–140px。
  - 说明文字每行不超过 12 个汉字。
  - 自动检查（`npm run zq:layout`）同时检查以上规则：2165 帧，0 个问题。

## v4 改了什么（旁白、文案、知识点不变）

- **镜头**：从 70 个镜头（其中大量是自动“二次切入”造成的“小—大—小”跳变）减到 **32 个连续镜头**，平均约 4.5 秒。
  - 删除了按时长自动切开的逻辑（`SPLIT`、`cutIn`、`shot.part`），也删除了 2D 镜头第二段的网格推近。
  - 每个镜头只做一种主动作：推近、横移、升降或绕行；需要强调时，相机先到位再静止，由框选放大来完成。
  - 只在进入新章节、3D 与 2D 互切、切到全屏结论、换到真正不同的对象时硬切。
- **框选放大**：同一盘口或同一张图里的强调不再切特写。
  - 框外压暗约 13%，细发光框圈住目标，框内内容平滑放大到 1.10–1.12 倍（缓入 0.8 秒、停留、同速缓出）。
  - 说明卡用引线连到框上。
  - 用在 6 处：价差条、深度图缺口、成交带、买单四档（流动性）、卖一（吃单）、前高上方的止损堆。
- **闪切和音效**：颜色闪切只留在 7 个章节起点；停止跳档时的白闪降到原来的三分之一。普通切点不再有 tick，只有章节切点有 whoosh + thud。
- **不用等号、斜章表达逻辑**：
  - **A. 没人跨过去**：深度图里买单光点两次冲向价差，被缺口边缘弹回，成交笔数一直是 0；下一镜头真正跨过去，计数才变 1。
  - **B. 买入量与卖出量**：两张 4 手订单从两边滑到中间，合并锁定成一张“成交凭证”，买卖两列数字对齐。
  - **C. 流动性**：价格阶梯的买单四档被扫描线逐档点亮，标出“可立即成交”，市价卖单一碰到买一就成交。
  - **D. 空头止损买单**：先是一张灰色虚线“幽灵订单 · 触发前隐藏”；价格碰到触发价，它翻转成琥珀色“主动买单”，飞向卖盘。
  - **E. 几类人**：一个巨大的黑影轮廓（“一个庄家？”）裂成四块，飞到做市商、机构、套保者、短线交易者身上，各自接上订单流。
  - **F. 套保者**：小额盈亏卡片撞上盾牌后被红叉划掉，旁边的风险敞口条缩到约等于 0。
  - **G. 操纵**：左边一张很小的红色“违规证据”卡，红框只框住它；右边大半个画面是四路“日常需求流”，用比例表达“存在，但只解释得了少数行情”。
  - **H. 挂单可以撤 / 只提高概率**：价格上方的挂单直接从盘口撤走并变暗；旁边的概率仪表只填到 70%，其余标“不确定”。
  - 斜印章只剩一处状态章“常见误解”；所有语义文字保持水平。
- **保留**：v3 的安全区、防遮挡和自动检查（`npm run zq:layout`，v4 结果 2165 帧、0 个问题），以及结尾订单池到足迹图的擦除过渡。

## 渲染（一条命令）

在 `claude/studio` 目录下运行：

```bash
npm run zq:render
```

- 输出：`D:\claude视频\zhanqian-awakening-ep01-v6.mp4`（文件夹不存在会自动创建）。
- 编码：H.264 High，yuv420p（BT.709），CRF 16，AAC 320 kbps，30 fps。
- 这条命令用 ANGLE 调用显卡渲染（`--gl=angle --concurrency=50%`）。

预计渲染时长（共 4330 帧）：

| 机器 | 预计时长 |
|---|---|
| 有独立显卡（如 RTX 3060 以上） | 约 30–55 分钟 |
| 只有核显 | 约 1.5–2.5 小时 |
| 纯 CPU | 约 5–10 小时（每帧 4–8 秒；纯 2D 镜头更快） |

没有显卡、或 ANGLE 报错时，改用：

```bash
npm run zq:render:cpu
```

CPU 渲染太慢的话，可以把 3D 层降到 0.75 倍像素（文字和字幕仍然是原生分辨率）：

```bash
npx remotion render Zhanqian "D:/claude视频/zhanqian-awakening-ep01-v6.mp4" --props="{\"dpr\":0.75}" --audio-codec=aac --audio-bitrate=320k
```

## 2K 渲染（1440×2560，交付用）

```bash
npm run zq:render:2k
```

- 输出：`D:\claude视频\zhanqian-awakening-ep01-v6-2k.mp4`。
- 参数：`--scale=1.3333333333`，3D `dpr: 1.333`（来自 `studio/props/zhanqian-2k.json`），文字和图表按 2K 重新排版，不是放大 1080p；30 fps，H.264 High，yuv420p（BT.709），CRF 16，AAC 320 kbps。
- 完整命令（可以直接粘贴）：

```bash
npx remotion render Zhanqian "D:/claude视频/zhanqian-awakening-ep01-v6-2k.mp4" --props=props/zhanqian-2k.json --scale=1.3333333333 --gl=angle --concurrency=50% --image-format=jpeg --jpeg-quality=95 --codec=h264 --crf=16 --pixel-format=yuv420p --color-space=bt709 --audio-codec=aac --audio-bitrate=320k
```

预计 2K 渲染时长（5173 帧）：

| 机器 | 预计时长 |
|---|---|
| 独立显卡（RTX 3060 以上） | 约 60–110 分钟 |
| 只有核显 | 约 3–5.5 小时 |
| 纯 CPU | 约 11–22 小时 |

渲染完可以检查：`npm run zq:qc:2k`。`zq:render:4k` 还在 package.json 里，但 v4 没有验证 4K 全片，交付请用 2K。

## 修改内容

| 想改什么 | 改哪里 | 之后运行 |
|---|---|---|
| 口播文字、停顿、语速 | `studio/src/zhanqian/script.json` | `npm run zq:vo`、`npm run zq:audio`、`npm run zq:srt` |
| 镜头表（切点、构图、闪切颜色） | `studio/src/zhanqian/director.ts` 里的 `SH` | `npm run zq:audio`（切点音效跟着镜头表走） |
| 屏幕上的文字 | `studio/src/zhanqian/copy.ts` | 不用跑别的 |
| 订单簿的节奏（哪一档什么时候被吃、止损何时触发） | `studio/src/zhanqian/book.ts`（盘口阶梯、成交带、成交量、Delta 都从这一张表算出来） | `npm run zq:audio` |
| 3D 场景和材质 | `studio/src/zhanqian/Scene.tsx` | 不用跑别的 |
| 数据面板、标注、大字和字幕 | `studio/src/zhanqian/Hud.tsx`（画面分区常量 `SAFE / STRIP / MAIN / LOW / BOT` 在文件开头） | `npm run zq:layout`（检查安全区、字幕带、间距） |

`zq:audio` 会先用 `npx tsx` 把镜头表和盘口事件导出到 `src/zhanqian/cues.json`，再合成配乐和音效。重新生成音频需要 Python 3、`pip install edge-tts numpy scipy`，以及带 loudnorm 的完整版 FFmpeg。如果系统里没有，可以运行 `pip install imageio-ffmpeg`，然后把环境变量 `FFMPEG` 设为它的路径。

## 验收

- **自动检查**（可选，需要 Python 和完整版 FFmpeg）：

  ```bash
  npm run zq:qc
  ```

  检查时长（170–175 秒）、分辨率、编码、音画长度、响度（−14 LUFS）、削波、黑帧和冻结。
- **人工检查**：按 `storyboard.md` 的时间表逐段核对。重点看三处：
  1. 每句话是否只有一个视觉重点，标注是否和关键词同时出现、读完才离开；
  2. 节奏：v6 多了约 28 秒停顿，在手机上看是否拖沓（如果需要，可以在 `studio/src/zhanqian/script.json` 里缩短 `gap`，然后运行 `npm run zq:vo`、`npm run zq:audio` 和 `npm run zq:layout`）；
  3. 音效：只有章节起点有 whoosh，普通切点无声；
  4. 2:45–2:52 结尾：订单池连续推近，然后擦除成足迹图，中间不闪回。

# 07 数据可视化地球

场景：`scenes/GlobeScene.tsx`，几何工具：`lib/geo.ts`。

## 坐标约定

```ts
// 经度 0 朝向 +Z（镜头），东经为 +X，北为 +Y
x = cos(lat) * sin(lon)
y = sin(lat)
z = cos(lat) * cos(lon)
```

地球组旋转 `rotation.y = -经度`，就能把该经度转到正对镜头。

## 1. 点阵大陆（真实海岸线）

数据来自 `world-atlas/land-110m.json`（Natural Earth 1:110m）。

做法：**栅格化掩膜 + 斐波那契球采样**

1. 用 d3-geo 的等距圆柱投影，把陆地多边形画到 2048×1024 的 canvas 上
2. 在球面上生成 15 万个斐波那契螺旋点（分布非常均匀）
3. 每个点换算成经纬度，到 canvas 上查像素：是陆地就保留（约 4.3 万个点）

比逐点做多边形包含测试快几个数量级。

**莫尔纹**：斐波那契点阵太规则，会和屏幕像素网格形成"指纹状"干涉条纹。给每个点加 ±0.22° 的确定性抖动就能打散。

## 2. 点阵着色器的三个效果

- **揭示扫描**：按纬度从北极扫到南极，扫描前沿有一条高亮带
- **竖向扫描光**：一道沿 X 轴移动的亮带，营造"雷达扫描"的感觉
- **背面淡出**：按法线和视线的点积降低背面点的亮度，再由不透明的海洋球遮挡

## 3. 大圆飞线

```ts
// 球面线性插值（slerp），保证近对跖点的长航线也匀速
v = a * sin((1-t)Ω)/sinΩ + b * sin(tΩ)/sinΩ
// 按正弦抬升，航程越长弧线越高
r = R * (1 + sin(πt) * (0.08 + Ω/π * 0.42))
```

然后用 `TubeGeometry` 建成管道（160 段 × 6 边）。管道的 `uv.x` 就是沿线进度，片元着色器靠它实现：

- `uHead`：飞行头位置，`x > uHead` 的部分直接 discard（线还没"画"到那里）
- 拖尾：`smoothstep(uHead - 0.3, uHead, x)`
- 底线：已经画过的部分保留 22% 亮度
- 数据包：到达后每 46 帧发出一个高斯亮斑，沿线传输

`uHead` 从 0 走到 1.28（而不是 1），这样拖尾能完整"流出"终点。

落点效果：扩散光环（`expo.out` 放大并淡出）加上弹性尖刺（`elastic.out`）。

## 4. 3D 城市标签 → HTML

标签用 HTML 渲染（字体清晰、排版方便），位置由 3D 投影算出：

1. `globeState(frame)` 是纯函数，WebGL 场景和标签层**共用**它，保证完全对齐
2. 在 JS 里重建一个参数完全相同的 `PerspectiveCamera`
3. 城市坐标 × 地球的世界矩阵 → `vector.project(camera)` → 换算成像素
4. 用法线和视线的点积判断是否在背面，背面就隐藏

容易互相遮挡的标签（北京/上海，伦敦/巴黎）翻到左侧显示。

## 5. HUD 面板

- 标题：`clip-path: inset()` 从左往右擦出，渐变文字
- 数值：GSAP 补间加上 `@remotion/noise` 的 `noise2D` 微抖动，看起来像"实时数据"
- 线路日志：直接从 `timeline.json` 的 `arcs` 推导，状态在 TX 百分比和 SYNCED 之间切换，与飞线严格同步
- 迷你频谱柱：`noise2D(i, frame)` 驱动

## 换成自己的数据

改 `timeline.json` 的 `arcs`（起点、终点、开始帧、飞行时长），并在 `geo.ts` 的 `CITIES` 里补上经纬度即可。配乐里的到达提示音会自动跟着变。

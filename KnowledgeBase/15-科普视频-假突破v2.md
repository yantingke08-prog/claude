# 15 科普视频：假突破 v2（竖屏，全新重做）

用户否定了 v1（横版的玻璃关键位、铜金配色），要求从零重做，交付在 `E:\Video\outputs-v2\`。代码在 `studio/src/fakeout/`，与 v1 的 `src/breakout/` 完全独立。

- 成片规格：1080×1920，30fps，88.2 秒，H.264 + AAC，−14 LUFS。
- 配音：edge-tts `zh-CN-YunjianNeural`，默认语速。这个声音偏慢：同样 370 字的稿子念了 101 秒，所以删到 341 字。

- 静帧预览：`node scripts/breakout-stills.mjs FakeoutV2 out/fo <帧…>`，再用 `bash scripts/vsheet.sh` 拼成联系表。
- 事件帧（刺穿 / 崩落）在 `director.ts` 里由价格路径算出；`fakeout-score.py` 里复制了同一套算法，所以改 `barU` 时要两边一起改。

## 竖屏 3D 的经验

- 竖屏横向很窄。两个相距 7 个单位的物体（比如前高和新高）同框会太小，改用摇移分两镜；数值对比放到 HUD 卡片里。
- 每段的版式固定：信息卡片在上方（230–700px），3D 主体在中部，字幕在 1440px 附近。机位的 target 要让主体落在中部。
- 跟着主体动的点光源，在其他段落要关掉，否则别的 K 线上会出现一块高光。
- 站酷庆科黄油体个别字（如"它"）不好认。关键问句改用思源黑体 900。

## v3：镜头、标注和排版（口播、配乐和结论不变）

- 镜头统一为：完整图（80 根 K 线，停 1.2–1.5 秒）→ 琥珀色聚焦框 → 推近（22 帧）→ 依次出标注 → 回到全景。推近时宽度按几何比例变化，中心跟随宽度移动（`director.ts` 里的 `zoom`），看起来是"推进同一张图"。右上角的小地图用同色框标出当前视野。
- 镜面地板被去掉了：全景看整张图时，地板会切进图表。现在换成深色玻璃图表板和价格网格；雾的距离、激光粗细都随取景宽度自动调整。
- 字体：思源宋体 600 用于标题和结论，思源黑体 500/700 用于字幕和标注，IBM Plex Mono 500 用于数字。字幕 56px，放在深色底板上；标注不小于 34px。
- 渲染交给用户在本地完成（`npm run fo:render:gpu`），说明见 `outputs-v3/README.md`。

## v4：同一根突破，三种结局（132.7 秒，重配旁白）

- 结构：钩子（共享突破 K 刺穿后分裂成三行）→ 三行对比 A/B/C → 主图讲机制 → 主图讲信号 → 回到三行讲应对 → 三行总结。两处换场用约 0.9 秒的暗场过渡。
- 三行对比和主图在同一个 3D 世界里：对比页放在 x = 400，镜头按段落切换位置。当前行放大 6%；其他行叠 70% 的暗层（亮度约 30%）。边框、聚光、标签都在 HUD 里，用投影跟住行的位置。
- 数据：`market.ts` 里的 OHLCV + Delta 只生成一次（固定种子加手写关键 K 线）。`bar(o, i)` 对 i ≤ 0 返回同一份数据，保证三种结局在突破前完全一致。历史上涨段按"每段的终点价"来引导，不能用"每段总涨幅"——否则随机游走会跑偏，进震荡段时被 clamp 成一根巨型 K 线。
- `events.json` 同时给 `director.ts` 和 `fakeout-score.py` 用，刺穿、崩落这些事件帧只定义一次。u 轨道用线性关键帧，保证穿越 5000 的那一帧刚好落在事件帧上。
- 本地渲染命令：`npm run fo:render:gpu`；验收：`npm run fo:qc`（时长窗口 120–140 秒）。

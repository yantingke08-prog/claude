# 02 工作流程

## 标准流程

```
分镜 → timeline.json → 单场景开发 → 关键帧抽查 → 配乐 → 全片渲染 → 质检
```

### 1. 先写分镜，落到 timeline.json

每个场景写清楚：时长（帧）、镜头怎么动、每个元素什么时候出现、哪些时刻是"重拍"（需要配音效的冲击点）。

重拍点写进 `src/timeline.json` 的 `cues`。**画面和配乐都从这个文件读时间**，所以改一个数字，两边同时跟着变，永远不会音画错位。

```json
"cues": {
  "intro": { "riser": [40, 148], "hit": [150] }
}
```

帧号是**场景内的局部帧**；场景在全片中的起点由 `lib/timeline.ts` 的 `sceneStart()` 统一计算（已扣除转场重叠）。

### 2. 单场景开发

`Root.tsx` 里每个场景都注册成了独立合成（Scenes 文件夹），可以单独预览、单独出图：

```bash
npm run studio
```

### 3. 关键帧抽查（最重要的提效手段）

全片渲染很慢，改一处就整片重渲是在浪费时间。改完先出几张关键帧：

```bash
npx remotion still Globe out/globe_160.png --frame=160
```

每个场景至少检查：入场中途、信息最满的一帧、出场前。

### 4. 配乐

```bash
npm run audio
```

生成 `public/soundtrack.wav`，自动响度标准化到 −14 LUFS。

### 5. 全片渲染

```bash
npm run render
```

输出 `out/showreel.mp4`（H.264，CRF 16，yuv420p，兼容所有平台）。

### 6. 质检

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,duration -of compact out/showreel.mp4
```

```bash
ffmpeg -i out/showreel.mp4 -af ebur128=framelog=quiet -f null -
```

再抽几帧看画面：

```bash
ffmpeg -ss 12 -i out/showreel.mp4 -frames:v 1 out/check_12s.png
```

## 常用命令速查

| 目的 | 命令 |
|---|---|
| 预览工作室 | `npm run studio` |
| 类型检查 | `npm run typecheck` |
| 出单帧 | `npx remotion still <合成ID> out/x.png --frame=N` |
| 只渲一段 | `npx remotion render Showreel out/part.mp4 --frames=200-400` |
| 竖屏版 | 在 `Root.tsx` 新增 1080×1920 合成，复用场景组件 |
| 导出 GIF | `ffmpeg -i out/showreel.mp4 -vf "fps=15,scale=960:-1:flags=lanczos" out/preview.gif` |
| 压缩发布版 | `ffmpeg -i out/showreel.mp4 -c:v libx264 -crf 22 -preset slow -c:a aac -b:a 192k out/web.mp4` |
| 排查渲染问题 | 加 `--log=verbose` 查看浏览器控制台 |

## 渲染耗时参考（本机：4 核 Xeon，无 GPU）

- 单帧 still（含打包）：约 20～30 秒
- 全片 1173 帧：约 38 分钟（并发 2，SwiftShader），约 2 秒/帧
- 只改了某一段时：用 `--frames=起-止 --muted` 只渲那一段，再用 ffmpeg 的 trim + concat 拼回，并重新混入音频（本片结尾就是这样修改的，8 分钟搞定）

有 GPU 时改用 `angle` 后端，详见 [01-环境与目录](01-环境与目录.md)。
